# AGENTS.md

Telegram-бот со списком задач: Go, SQLite, long polling. Пользовательская документация — в `README.md`, здесь — правила работы с кодом.

## Команды

```bash
go test ./... -race     # тесты (парсер и хранилище)
go vet ./...
gofmt -w .
go build -o todo-bot .
TELEGRAM_BOT_TOKEN=... go run .
```

`go run` без токена падает сразу — это ожидаемо. Живой Telegram не нужен для тестов.

## Структура

- `main.go` — env (`TELEGRAM_BOT_TOKEN`, `DB_PATH`, `TZ`), открытие БД, запуск.
- `internal/parser` — разбор русских фраз времени. Чистый пакет без зависимостей.
- `internal/store` — SQLite-репозиторий задач. UTC unix seconds, `MaxOpenConns(1)`.
- `internal/bot` — хендлеры Telegram, черновики, воркер напоминаний.

## Инварианты, которые нельзя ломать

### Парсер

Поддерживаемые формы перечислены в шапке `parser.go`. Любая новая форма — новый регекс + кейсы в табличном тесте `parser_test.go`.

- Нет времени во фразе → `09:00`.
- Дата без года в прошлом → следующий год; дата с годом в прошлом → `ErrPast`.
- Явно прошедшее время (`вчера`) → `ErrPast`, мусор → `ErrParse`.
- Сравнение дат идёт по календарному дню, а не по инстанту: «06.11» в тот же день с прошедшим 09:00 — `ErrPast`, а не следующий год.
- Время возвращается в локации `now`, не в UTC.

### Хранилище

- Все моменты — `INTEGER` unix seconds в UTC, конвертация только при показе.
- Все запросы к списку и к конкретной задаче фильтруют `user_id`; чужой id → `ErrNoTask`. Исключения по делу: `DueReminders` глобальный (воркер) и `MarkReminded` идёт по `id`.
- `due_at IS NULL` в `ORDER BY` — задачи со сроком идут первыми.
- Активная задача = `done = 0`; выполненные не удаляются.
- Схема создаётся через `CREATE TABLE IF NOT EXISTS`. Миграций нет: менять схему — только вместе с продуманным апгрейдом существующего `todo.db`. Пример — `photo_file_id`: на старте проверяется `pragma_table_info` и при необходимости делается `ALTER TABLE ADD COLUMN`.
- Фото — Telegram `file_id` в `tasks.photo_file_id`, одно на задачу; файлы не скачиваются.
- Не добавлять `SetMaxOpenConns(>1)`: SQLite-записи должны оставаться сериализованными.

### Бот

- Только личные чаты; сообщения и callbacks из групп игнорируются.
- Доступ открыт всем, изоляция — по `user_id` (= id личного чата).
- Текст задачи ≤ 200 рун; список — 10 задач на страницу.
- Фото с подписью создаёт задачу: подпись — текст. Фото без подписи прикрепляется к текущему черновику. Хранится один `file_id` на задачу.
- Черновики `/add` живут в памяти: новый `/add` заменяет, `/cancel` удаляет, рестарт теряет. Старый callback после рестарта должен отвечать «начните заново».
- Задача создаётся только после выбора времени или «без напоминания».
- Callback data — стабильный формат, менять только вместе с хендлерами:
  - `w:<draftID>:<unix|none|other>` — пресеты времени;
  - `l:<page>` — пагинация;
  - `t:<page>:<taskID>` / `d:<page>:<taskID>` — готово/удалить в списке;
  - `p:<page>:<taskID>` — посмотреть фото задачи;
  - `rt:<taskID>` / `rd:<taskID>` — кнопки в напоминании.
- Напоминание: раз в 30 с, одно на задачу, только после успешной отправки помечается `reminded_at`; просроченные отправляются при старте. Рассчитан на один экземпляр. С фото — `sendPhoto`, при ошибке — текстом; кнопки такого напоминания правятся через `EditMessageCaption`, а не `EditMessageText`.
- UI-тексты — по-русски, простым текстом без `parse_mode`.
- Команды регистрируются через `MatchTypeCommandStartOnly`; всё неизвестное с `/` обрабатывает default-хендлер.

## Тесты

Согласованный объём — парсер и репозиторий. Новая нетривиальная логика (ветвление, парсинг, работа с деньгами/безопасностью) должна получить тест или переиспользовать существующий табличный набор. Bot-логика покрывается вручную в Telegram.

## Зависимости

`github.com/go-telegram/bot` и `modernc.org/sqlite` (pure Go, без cgo). Не добавлять новую зависимость ради нескольких строк; для парсинга дат уже есть свой пакет.
